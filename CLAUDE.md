# NFL Owner Simulator: guide for Claude

Read this before exploring the code. It is the map; open files only for the
parts a task touches. README.md is the player-facing description of features.

## Ground rules

- The owner never sees a rating. `HIDDEN_RATINGS`, `HIDDEN_STAFF` and every
  `*Hidden` type are engine-only; the UI shows stats, contracts and staff
  reports (`reports.ts`, `perceivedAbility`, `coachView`). `coachView` sharpens
  with the practice reps in `state.program` (`coachRead` in `staff.ts`), so
  depth charts move during camp.
- Real data first (`data/`, built by `pipeline/`). Made-up things (agents,
  outlets, prospects, generated coaches) are labeled as such in comments.
- Everything is deterministic from the save's seed: use `rngFor(state, ...)`
  from `rng.ts`, never `Math.random`.
- Dates are ISO `yyyy-mm-dd` strings in Eastern time; compare them as strings.
- Comments explain the football or business rule, in plain sentences, like the
  ones already in the file. Match the surrounding style.

## Commands

```
npm test                    # all tests, dot output (~90 s with warm fixtures, ~3 min cold)
npx vitest run tests/<file> # one area while iterating
npm run build               # tsc + dist/index.html + dist/game.html (the claude.ai page, ~8 MB)
npx vite-node tests/<x>-report.ts [args]   # calibration reports (run from the repo root)
```

`tsc` only covers `src/`; tests are checked when vitest runs them.

## How the engine works

- **One mutable `GameState`** (`types.ts`, `interface GameState`). Engine
  functions take `state` and change it in place. The UI wraps every action in
  `step(fn)` in `ui/GameShell.tsx`, which runs it and calls `changed()` to
  re-render and autosave.
- **The clock** runs by the minute inside a day (`state.clock`, `clock.ts`):
  `advanceTo(state, minute)`/`advanceHours` in `season.ts` run today's moments
  in order (`nextMoment`): kickoffs at `timeET` (`kickoffGame` in `gametime.ts`
  plays the whole game at once into `state.live`, shown as far as the clock has
  run by `liveRows`; `finishGame` books it at the whistle), and on a
  `DEADLINE_KEYS` day `passDeadline` at 4 PM runs the front office's day
  (`frontOfficeDay`: cutdown through `campDaily`) and sets `DEADLINE_MARK`, read
  by `pastDeadline` (trade window, `canTag`, `inWindow`, expired deals).
  Reaching midnight ends the day.
- **The day loop** is `endDay` (via `advanceDay`, the rest of today) in `season.ts`: the owner's pending events,
  then the daily hooks in this order: `offseasonDaily`,
  `carouselDaily`, `positionCoachesDaily`, `formerPlayersDaily`, `contractsDaily`, `contractExtrasDaily`, `incentivesDaily`, `capMovesDaily`, `faDaily`,
  `tradesDaily`, `springDaily`, `campDaily`, `coachRoomDaily`, `ownersDaily`, `leagueOfficeDaily`, `laborDaily`, `leagueMoneyDaily`, `complianceDaily`, `crisisDaily`, `legalDaily`, `hostingDaily`, `disciplineDaily`, `draftDaily`, `visitsDaily`, `proDayDaily`, `collegeDaily`, `cfbDaily`,
  `scoutingDaily`, `scoutOpsDaily`, weekly upkeep and playoffs, `economyDaily`, `businessDaily`, `shocksDaily`, `commerceDaily`, `fansDaily`, `sponsorsDaily`, `merchDaily`, `teamMediaDaily`, `facilitiesDaily`, `communityDaily`, `departmentsDaily`,
  `projectsDaily`, `stadiumLabDaily`, `groundsDaily`, `constructionDaily`, `politicsDaily`, `relocationDaily`, `expansionDaily`, `globalDaily`, `leasesDaily`, `debtDaily`, `booksDaily`, `treasuryDaily`, `investorsDaily`, `wealthDaily`, `franchiseDaily`, `erasDaily`, `takeoverDaily`, `successionDaily`, `rivalsDaily`, `causesDaily`, `archiveDaily`, `officeDaily`, `ownerCallsDaily`, `crossroadsDaily`, `boardroomDaily`, `problemsDaily`, `peopleDaily`, `standingDaily`, `gameOpsDaily`, `analyticsDaily`, `analystsDaily`, `lockerDaily`, `lockerRoomDaily`, `trainingDaily`, `medicalDaily`, `careDaily`, `gameWeekDaily`, `bonusesDaily`, `honorsDaily`, `hallOfFameDaily`, `hindsightDaily`, `recordsDaily`, `mediaDaily`, `reviewDaily`, `pressDaily`, `achievementsDaily`. The day after the draft, `startNewSeason` (`seasons.ts`) rolls
  the league over. A new system adds an `xxxDaily(state)` and one line here.
- **Season context** lives in module globals in `league.ts`: `RULES`
  (`RULES.keyDates`, often aliased `K` or `KEY`), `SCHEDULE`, `GAMES_BY_DATE`.
  `setLeagueSeason` swaps them in place when a later season is applied, so a
  cached `K.draftStart` is right only for the season currently applied.
  `BASE_KEY_DATES` and `BASE_SCHEDULE` are always 2026.
- **Saves**: `save/codec.ts`. `migrate` brings old saves forward and calls the
  `ensureX(state)` helpers that create a system's slice of state when it is
  missing. A new optional field on `GameState` needs an `ensureX` (or a `??=`
  where it's read) so old saves still load. Saves must not change format
  without a migration. `save/local.ts` serializes autosave writes (merging
  ones that queue up), keeps three rotating recovery copies and reports its
  status to `SaveIndicator` (`ui/SaveGuard.tsx`); `holdAutosave` stops writes
  after a failed step. `save/era.ts` reloads into another start season only
  after a confirmed save. Ids in capped lists come from `nextId` (`ids.ts`),
  never a list's length.
- **Messages**: `send` (owner's inbox) and `news(state, topic, text)` (league
  wire) in `inbox.ts`; the topic (`NewsTopic`) routes the line to the story
  engine's wire desk (`log` for events already covered elsewhere, `games`,
  `draft` and `college` keep the old wire); stories go through `addStory` in
  `outlets.ts`.

## Reading big files

Twelve engine files run 900 to 1,430 lines. Don't read them whole:

- List what a file exports: `grep -n "^export" src/engine/<file>.ts`.
- Find a type: `grep -n "interface Foo" -A30 src/engine/types*.ts` (the types
  files run 200 to 1,100 lines; never read one whole).
- Then read only the line range you need.

Split as you go: when a step adds a sizable new feature to a file that is
already over 1,000 lines, put it in a new module instead.

## Tests and calibration

- `tests/fixtures.ts` saves played games in `node_modules/.cache/nfl-fixtures`,
  keyed by a hash of `src/engine`, `src/save` and `data`.
  `stateAt(team, seed, at)` returns a copy at season end (`at` omitted), a 2026
  key-date name (`"draftStart"`) or a date. Use it in new tests instead of
  `newGame` plus a long `advanceDay` loop, unless the test is about the path
  (every-day coverage, determinism).
- While iterating, run only the affected test file. Run `npm test` once before
  the PR.
- Reports take `FROM=<key date|date|end>` to start from a saved state instead
  of a new game. Add `FIXTURES=stale` to reuse a state saved by older code, so
  tuning the offseason doesn't replay the season every run:
  `FIXTURES=stale FROM=end npx vite-node tests/fa-report.ts 7`.
  Finish with one full run without them.

Calibration targets (what "healthy" looked like when each system shipped):

- Season sim (`calibrate.ts`, `season.test.ts`): NFL-like scoring, home edge
  and parity; upsets common. Injuries ~2.8 per team-game (`maybeInjure` in
  sim.ts, practice odds in `practiceInjuries` in season.ts), ~7 per club on IR
  at season end, starting QBs taking ~90% of their team's attempts; scoring
  was retuned (`baseComp` in simpass.ts) when injuries went up, so retune both
  together. A voted 35-second play clock adds about 4% more plays.
- Player stats (`stats-report.ts 3`, about 40 s a season; ranges in
  `tests/statspread.ts`, also judged by `balance-report.ts`, test
  `statspread.test.ts`): how totals split among players: ~25 1,000-yard
  receivers and ~20-25 10-sack players a year, top target ~24% of a team's
  targets, sacks EDGE ~.5 / IDL ~.25 / LB+DB ~.2. Target weights in
  `pickPass` (the first read and the throw's depth together, tilted by the
  receiver's game; `pickTarget` only for the second read), sack credit in `sack`, rotation in `defenseLineup` (`simteam.ts`; `pickPass` and `sack` in `simpass.ts`).
  The report also prints whole leaderboards (ranks 1-64 for 27 stats,
  `tests/realcurves.ts`) next to real 2024 and 2025, and each team's target
  and carry shares by rank (real targets .24 .18 .14 .11 .09; carries .50 .23
  .12). Receiver and back rotation in `offenseLineup`, the workhorse share
  from the RB1-RB2 gap. Yards per catch runs ~17 at the top to ~10.5 at rank
  64 (vertical receivers run longer routes, `stretch`); the passing TD leader
  ~42 (real 43-46) from red-zone trust in elite quarterbacks in
  `passProbability`.
- Seasons loop (`seasons-report.ts 4 7`, about 1 min a season): top-30
  talent steady year to year; ~32 comp picks a year; 85+ players drift slowly
  (446 to ~420 over four seasons); every team near or under the cap by year 4.
- Coaching (`coaching-report.ts 3 7`, about 4 min): wins against roster talent and each staff number. Head coaches' `command` (staff.ts, a per-snap edge in `baseEdge`) puts the top and bottom quarters 1 to 1.5 wins apart beyond the roster; talent stays the biggest single factor; the teaching staff's link to young players' growth (share of their room) is printed beside it. `CoachSeason.exp` is the kickoff pick from `staff.expect`. The same report prints the locker room: starters' mood and chemistry spread between clubs and their quarter gaps in wins (`lockerroom.ts`: `lockerRoomDaily` moves every player's mood a fifth of the way toward `moodTarget` on camp and season Tuesdays; `speakUp` sends our unhappy starters' memos via `resolveLockerMemo`; `moraleDrag` in staff.ts from 60 down and a small lift above 78; `chemistryEdge` 0.04 a point, up to ±1.2). Mood and chemistry gaps in the report include reverse cause (winning teams are happier); the causal share is about a point of edge for 25 points of chemistry, roughly a win.
- Owner decisions (`connect-report.ts 4 7 DET [idle|careless]`): an advised owner gets ~15-30 memos a season (home-game prices, the budget review, crossroads, board meetings) and should finish ahead of an idle owner in club value or fans, a careless one behind. Gate: a sold-out club's extra demand turns into money through `power` in `gateModel` (project demand and marketing raise the season-ticket price); `perCap` reaches parking and gate merchandise. Department levels: marketing, game day and community also move `fans.core` each season (`seasonEnd` in fans.ts).
- Parity (`parity-report.ts 8 7`, about 1.2 min a season): win% spread .17-.20, year-to-year win r .25-.45 (mean over pairs; NFL ~.33), ~70% of starters back with their club, club talent sd ~1.6-1.9 after year two, 85+ players ~430-480 and level. Rookies give up up to `ENTRY_MAX` (4) points in year one in `nflOutcome` (outcomes.ts), 70% of it off their potential; without it the 85+ count climbed ~27% in seven seasons. The weakest starters (p10) still drift up ~0.5 a season.
- Carousel (`carousel-report.ts 3 11`): 2 to 10 HC changes a year, no search
  left open, ~880 people tracked (with position coaches).
- Trades (`trade-report.ts`): ~30 to 50 a year with a deadline rush.
- Long careers (`longrun-report.ts 11 7`, about 1.5 min a season): 3 to 7
  CPU tags a year; market tops steady (QB top deal at most ~25% of the cap,
  set by `marketCeiling` in `market.ts`); league-wide player cash near 100%
  of the cap; every team at or over zero space at each rollover.
- Release checks (`docs/balance.md`): `src/engine/invariants.ts` lists hard
  errors (player on an unknown team, a contract for another team, more than 53
  in season, non-numbers in cap or cash, two head coaches or GMs, one owner
  controlling two clubs, repeated decision ids). `tests/balance-report.ts
  <seasons> <seeds,...>` (env `ERA`, `RECESSION`, `OUT`) runs them at season
  start, the trade deadline, the Super Bowl and season end, checks every club
  is under the cap once the league year opens, and judges balance numbers
  against the documented ranges as warnings. A hard error exits 1 and writes a
  case to `tests/regressions/`, which `regressions.test.ts` replays;
  `roundtrip.test.ts` checks a reloaded save plays on identically (caches kept
  on the state object must not outlive the game day). CI
  (`.github/workflows/ci.yml`) typechecks, tests and builds every pull request;
  `long-run.yml` runs seeds, a historical start and a recession weekly.
- Connectivity (`connect-report.ts [seasons] [seed] [team] [idle]`, about 1.2 min
  a season; `SAVE=<file.gz>` keeps the final state): plays with an owner who
  decides every memo as recommended and answers the press (or, with `idle`,
  does nothing) and prints, per season, money by ledger line, fans, the
  building's trust, the audiences, the desk and the state's slices by size.
  A row marked `=` never moved (a system nobody feeds); a slice that grows
  every season is listed. Healthy: audiences hold in a band (press and lenders
  forgive slowly, `pressMemory` in standing.ts, the monthly drift in
  `debtDaily`), no ledger line drops to zero for a year (`refillCategory` in
  commerce.ts after a sponsor default), audit findings get fixed (the queue's
  `problem:audit`, `chiefFixes` in treasury.ts). `connectivity.test.ts` holds
  one test per link this check found missing.
- Old saves: `saves.test.ts` loads gzipped saves made by earlier versions
  (`tests/saves/`). Add one when a step changes the save shape.
- Decades (`decades-report.ts 50 7`, about 1.5 min a season): season time levels
  off near 100 s after year 8; the compressed save grows ~120 KB a year early and
  less once the capped logs fill (career stats are the lasting growth); 0 teams
  over the cap; 5-12 HC firings and 25-47 trades a year.
- Expansion (`expansion.test.ts`; force it in a harness with `forceExpansion(s, { joins: RULES.season + 1 })` then play on from a February state): new clubs about league-low starter talent and 3 to 5 wins in their first season (real debuts 2-14 to 7-9). Never hard-code 32 clubs: use `TEAMS.length` and `VOTES_TO_PASS`.
- Known lessons: retired players stay in `state.players` and outnumber the
  league after a few decades: daily loops walk `liveIds(state)` (`live.ts`), and
  nothing should copy `state.contracts` (`{ ...state.contracts }`) in a hot path;
  fixed-dollar thresholds break as the cap grows (scale with
  `capScale` in `market.ts`); CPU bids must target players a team can afford;
  extensions must fit next year's cap; trades count the dead money they leave;
  a deal's share of the cap must be measured on the same cap it was priced on
  (`capAtSigning`), or every market ratchets up; anything that pays a player
  must call `payCash` (`finance.ts`) or the cash side drifts from the cap.

## Shipping a step

1. Branch, build, iterate with targeted tests and quick reports.
2. `npm test` and `npm run build` once, then open the PR, merge it yourself.
3. Republish `dist/game.html` to the same artifact URL (kept in project
   memory) with its existing capabilities and the `anim/`, `art/`, `lab/` and `packs/` files in its files map. Don't print or Read the 8 MB page. The build drops player fields the game never reads (`slimPlayers` in `vite.config.ts`).
4. Update README.md (Status and Code layout) only for what changed, and the
   project memory for anything a later step needs.
